# Subagent roster integration test plan

The baseline selects only the ViewModel case on unchanged production. After the
repair run these four exact JVM selectors, including the two controller controls:

```powershell
scripts/android-lane.ps1 --timeout-seconds 30 gradle :app:testSideloadDebugUnitTest `
  --tests '*ChatViewModelGatewayInboundTurnTest.authoritativeRosterRemovesOnlyMissingIdentifiedChildCardsAfterParentCompletion' `
  --tests '*GatewayChatClientTest.subagentRosterRequiresInitializedOwnerAndCompleteValidSnapshot' `
  --tests '*SubagentActivityControllerTest.rosterAbsenceRetiresOnlyComparableUnchangedChildren' `
  --tests '*SubagentActivityControllerTest.detached child survives parent completion and a new turn with stable preview identity' `
  --no-daemon --console=plain
```

The VM case starts two synthetic identified children, completes their parent
without child terminal frames, and returns a roster with only one still live.
Only the missing card disappears; no prompt or interrupt is generated by the
reconciliation. This checks the production state flow, not Compose rendering.

The client case must reject passive prewarm as unconfirmed, then positively
read a roster after actual parent completion. Missing arrays, malformed numeric
IDs and unsupported methods must fail, not masquerade as empty rosters. Explicit
terminal status rows are no longer live. Check the exact RPC count and reject a
delayed result after owner change. Only the changed client test is rerun when
strengthening its completion barrier/negative controls; product stays unchanged.

  -k subagent_roster_after_parent_completion -v

  --scenario-manifest test-fixtures/vanilla-gateway/vanilla_gateway/scenarios/subagent_roster_reconcile.json `

The fixture proves the complete identified roster response after parent terminal
and foreign-session refusal. Source conformance selects only the manifest's
message-complete and subagent-roster requirements; no Gateway/provider is started.
